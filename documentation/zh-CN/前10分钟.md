# 最初 10 分钟

[English](../first-10-minutes.md) | [Español](../es/primeros-10-minutos.md) | [Português](../pt-BR/primeiros-10-minutos.md) | **简体中文**

一个极小的服务，一个 xUnit 测试，每一步都是真实输出。下面的一切都是针对
本仓库自身的包真实运行过的 — 没有想象出来的输出。

## 1. 添加包

```xml
<PackageReference Include="NarrativeTrace.Core" Version="0.1.2" />
<PackageReference Include="NarrativeTrace.Runtime" Version="0.1.2" />
<PackageReference Include="NarrativeTrace.Proxy" Version="0.1.2" />
<PackageReference Include="NarrativeTrace.Testing.Xunit" Version="0.1.2" />
```

## 2. 添加一个服务接口及其实现

```csharp
using NarrativeTrace.Core.Annotation;

public interface IOrderService
{
    string PlaceOrder(
        string customerId, string productId, int quantity,
        [NotTraced] string internalNote);
}

public sealed class OrderService : IOrderService
{
    public string PlaceOrder(
        string customerId, string productId, int quantity, string internalNote)
        => $"confirmed:{customerId}:{productId}:{quantity}";
}
```

`[NotTraced]` 加在**接口**的参数上 — proxy 是针对接口的方法元数据进行调度
的，所以特性也是从那里读取的。

## 3. 添加一个 xUnit 测试

```csharp
using NarrativeTrace.Proxy;
using NarrativeTrace.TestingXunit;
using Xunit;

public sealed class OrderServiceTests : IClassFixture<NarrativeFixture>
{
    private readonly NarrativeFixture _fixture;
    public OrderServiceTests(NarrativeFixture fixture) => _fixture = fixture;

    [Fact]
    public void Places_an_order()
    {
        _fixture.Run(nameof(Places_an_order), ctx =>
        {
            var orders = NarrativeTraceProxy.Create<IOrderService>(new OrderService(), ctx);
            orders.PlaceOrder("cust-1", "book-123", 2, "gift wrap");
        });

        _fixture.WriteArtifacts(nameof(OrderServiceTests), nameof(Places_an_order), failed: false);
    }
}
```

`WriteArtifacts` 是显式写入文件的那一步 — 如果不调用它，`NarrativeFixture`
本身是惰性的，因此在普通测试运行中不会产生任何开销。

## 4. 运行测试套件

```bash
export NARRATIVETRACE_OUTPUT=true
dotnet test
```

## 5. 打开叙事

```text
narrativetrace-output/traces/OrderServiceTests/places_an_order.md
```

你会看到这次调用被渲染出来，包含除 `internalNote`(第 7 步会讲到)之外的
每一个参数、返回值和耗时 — 全部由上面的方法名和参数名生成，没有一条手写
的日志语句。

## 6. 把 `PlaceOrder` 重命名为 `Process`，看着清晰度下降

把方法(接口和实现)重命名为 `Process`，其余保持不变，然后对同一份已捕获
的追踪就地评分 — 不需要 CLI，不需要编译程序集这一步，只需要用分析器处理
你手头已有的追踪：

```csharp
using NarrativeTrace.Clarity;

var before = ClarityAnalyzer.Analyze(_fixture.CaptureTrace());
Console.WriteLine(before.Overall); // PlaceOrder：一个领域专属动词
```

重命名后重新运行，再次打印 `Overall` — 它会下降，因为 `Process` 正是
分析器专门用来惩罚的那种泛化、空洞的动词。调用的其他一切都没变，只是
名字变了。

## 7. 添加 `[NotTraced]`，看到脱敏

重新打开第 5 步的 `places_an_order.md`：`internalNote` 从未以真实值的
形式出现过。要显式看到这个*标记*，把追踪渲染成文本，而不是读 Markdown
文件：

```csharp
using NarrativeTrace.Core;

Console.WriteLine(IndentedTextRenderer.Render(_fixture.CaptureTrace()));
```

`internalNote` 参数会渲染成 `[REDACTED]` — 它在值被读取之前就已经被
替换掉了，而不是事后才被隐藏。去掉 `[NotTraced]` 再重新运行，就能看到
真实值出现在原来的位置，这样两者的差异一目了然。

## 8. 查看对 AI 安全的结构化产物

在 Markdown 文件旁边，同一次运行还写出了第二个不含值的文件：

```text
narrativetrace-output/structural/OrderServiceTests/places_an_order.nt
```

打开它：只有名称、调用层级和结果类型 — 没有 `internalNote`，没有
`customerId`，没有返回值。这个文件可以放心交给 AI 工具或粘贴进工单，
不需要经过脱敏审查，因为里面本来就没有什么需要脱敏的东西。关于它已经
验证过的内容，参见[隐私与脱敏](隐私与脱敏.md#保证)；关于要不要保留它，
参见[应提交的内容](应提交的内容.md)。
