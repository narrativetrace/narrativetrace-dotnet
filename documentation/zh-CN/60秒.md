# 60 秒看到一条追踪

[English](../sixty-seconds.md) | [Español](../es/sesenta-segundos.md) | [Português](../pt-BR/sessenta-segundos.md) | **简体中文**

没有日志语句，没有测试框架，没有需要打开的文件：一个控制台应用，一次
`dotnet run`，追踪就在你的终端里。下面的一切都是真实运行过的 — 输出是
粘贴过来的，不是想象出来的。

## 1. 新建控制台应用，添加这个包

```bash
dotnet new console -n Hello && cd Hello
dotnet add package NarrativeTrace.Proxy
```

只需一个包：`NarrativeTrace.Proxy` 依赖 `NarrativeTrace.Runtime`，后者又
依赖 `NarrativeTrace.Core` — `dotnet add package` 会解析整条依赖链，所以
下面用到的 `SyncNarrativeContext` 和 `IndentedTextRenderer` 不需要再额外
执行两次 `dotnet add package`。

## 2. 替换 Program.cs

`Program.cs` 通过 `NarrativeTraceConfig` 播种了一个固定的 `Traceparent`——
这与 `NarrativeTraceMiddleware` 从入站 `traceparent` 请求头中采纳的是同一种
线上格式——这样做纯粹是为了让本页嵌入的输出始终指向同一条追踪。你自己的
代码永远不会这样做：不设置 `initialTraceparent`，真实运行每次都会生成一个
随机的追踪 id，下面的三词名称正是从它派生而来，绝不是你自己选择的名字。

```csharp
using NarrativeTrace.Core;
using NarrativeTrace.Proxy;
using NarrativeTrace.Runtime;

// snippet:begin fixedTraceparent
// 一个固定的 W3C traceparent，通过 NarrativeTraceConfig 播种，使本页嵌入的输出始终指向
// 同一条追踪。真实运行时这里不会采纳任何值（或者通过 NarrativeTraceMiddleware 采纳一个真实
// 的入站请求头），每次都会得到一个全新的随机追踪 id。
const string DemoTraceparent = "00-a1b2c3d4a1b2c3d4a1b2c3d4a1b2c3d4-a1b2c3d4a1b2c3d4-01";
// snippet:end fixedTraceparent

var context = new SyncNarrativeContext(
    new NarrativeTraceConfig(initialTraceparent: Traceparent.Parse(DemoTraceparent)));
var orders = NarrativeTraceProxy.Create<IOrderService>(new OrderService(), context);

orders.PlaceOrder("cust-1", "book-123", 2);

Console.WriteLine(IndentedTextRenderer.Render(context.CaptureTrace()));

public interface IOrderService
{
    string PlaceOrder(string customerId, string productId, int quantity);
}

public sealed class OrderService : IOrderService
{
    public string PlaceOrder(string customerId, string productId, int quantity)
        => $"confirmed:{customerId}:{productId}:{quantity}";
}
```

## 3. 运行它

```bash
dotnet run
```

```text
trace: loose hook parks (a1b2c3d)

└── IOrderService.PlaceOrder(customerId: "cust-1", productId: "book-123", quantity: 2) → "confirmed:cust-1:book-123:2" — 10ms
```

（每次运行时耗时是唯一会变化的部分——上面这个固定的 traceparent 让其余一切，
包括追踪名称，都保持稳定。）

你没有写过一条日志语句。这条叙事完全来自你的方法名、参数名，以及你返回
的值。

## 刚刚发生了什么

- `NarrativeTraceProxy.Create<T>` 把 `OrderService` 包装在它的
  `IOrderService` 接口之下，并记录每一次通过这个包装器发起的调用。
- `SyncNarrativeContext` 把这次记录保存在内存中；`NarrativeTraceConfig()`
  默认就是 `TracingLevel.Detail` — 完整捕获参数与返回值，不需要打开任何
  开关。
- `CaptureTrace()` 返回被记录的树；上面就是 `IndentedTextRenderer` 打印出
  的结果。`MarkdownRenderer` 和 `ProseRenderer` 能把同一棵树渲染成其他
  格式。包装一个会调用其他已追踪服务的服务，这棵树就会嵌套 — 一次调用，
  一个故事。

## 把它发送到你的日志库

再加两个包，同一棵已捕获的树，没有新的捕获逻辑 — `TraceLogExporter` 会把
它重放到你的应用已经接好的那个 `ILogger` 上。

```bash
dotnet add package NarrativeTrace.Logging
dotnet add package Microsoft.Extensions.Logging.Console
```

下面带注释的这些行就是改动 — 一个完整的、可以直接粘贴使用的 `Program.cs`：

```csharp
using Microsoft.Extensions.Logging; // new: send the trace to an ILogger, not only the console
using Microsoft.Extensions.Logging.Console; // new: for LoggerColorBehavior below
using NarrativeTrace.Core;
using NarrativeTrace.Logging; // new: TraceLogExporter replays a captured trace onto an ILogger
using NarrativeTrace.Proxy;
using NarrativeTrace.Runtime;

// A fixed W3C traceparent, seeded through NarrativeTraceConfig so this page's embedded output
// always names the same trace. A real run adopts nothing here (or a real inbound request header,
// via NarrativeTraceMiddleware) and gets a fresh, randomly generated trace id every time.
const string DemoTraceparent = "00-a1b2c3d4a1b2c3d4a1b2c3d4a1b2c3d4-a1b2c3d4a1b2c3d4-01";

var context = new SyncNarrativeContext(
    new NarrativeTraceConfig(initialTraceparent: Traceparent.Parse(DemoTraceparent)));
var orders = NarrativeTraceProxy.Create<IOrderService>(new OrderService(), context);

orders.PlaceOrder("cust-1", "book-123", 2);

var tree = context.CaptureTrace(); // new: capture once, render it to both destinations below
Console.WriteLine(IndentedTextRenderer.Render(tree));

using var loggerFactory = LoggerFactory.Create(builder => // new: a second destination for the same trace
    builder.AddSimpleConsole(options => options.ColorBehavior = LoggerColorBehavior.Disabled)); // new: disable ANSI color codes so captured/piped output stays plain text
TraceLogExporter.ExportToLogger(tree, loggerFactory.CreateLogger("NarrativeTrace")); // new: replay the same tree onto the logger

public interface IOrderService
{
    string PlaceOrder(string customerId, string productId, int quantity);
}

public sealed class OrderService : IOrderService
{
    public string PlaceOrder(string customerId, string productId, int quantity)
        => $"confirmed:{customerId}:{productId}:{quantity}";
}
```

**为什么是 `using var` 里的 `AddSimpleConsole(… ColorBehavior.Disabled)`，
而不是直接用 `builder.AddConsole()`。** `Microsoft.Extensions.Logging.Console`
默认通过一个后台队列写入，所以经它记录的一行可能会在——或者与——逻辑上
后发生的同步 `Console.Write*` 输出交错着出现得很奇怪。这是控制台
provider 本身的平台行为，不是 NarrativeTrace 的缺陷，而且任意一侧写得
越多情况就越糟。真正管用的修复办法，已经通过反复运行这个示例验证过：
**在任何后续代码依赖顺序之前释放(`Dispose`)`ILoggerFactory`**——上面的
`using var` 会在 `Main` 结束时自动做到这一点，而 `Dispose()` 会一直阻塞，
直到 provider 的后台写入线程把队列中排队的一切都写完为止，这正是下面
的代码块每次都以相同顺序输出的原因。`ColorBehavior.Disabled` 解决的是
另一个不同的问题——它让 ANSI 转义码不会出现在你打算捕获、比较或粘贴到
这样一个页面里的输出中——所以两者都值得保留，但只有 `using var` 的释放
才能解决顺序问题。

```bash
dotnet run
```

```text
trace: loose hook parks (a1b2c3d)

└── IOrderService.PlaceOrder(customerId: "cust-1", productId: "book-123", quantity: 2) → "confirmed:cust-1:book-123:2" — 0ms

info: NarrativeTrace[1]
      IOrderService.PlaceOrder(customerId: "cust-1", productId: "book-123", quantity: 2) -> "confirmed:cust-1:book-123:2"
```

（每次运行时耗时是唯一会变化的部分——上面这个固定的 traceparent 让其余一切，
包括追踪名称，都保持稳定。）

同一条追踪，两个目的地：控制台渲染器保持完全不变，下面这条 `ILogger`
记录则证明这棵树确实落到了你已经在用的那个接收端 — 把 `AddSimpleConsole(...)`
换成你真正的 provider，其余什么都不用改。`NarrativeTrace.Logging` 的其他
入口（`LoggingNarrativeContext` 用于按调用实时记录日志，
`AddNarrativeLogging()` 用于 DI）见
[安装指南](../guides/zh-CN/安装指南.md)。
