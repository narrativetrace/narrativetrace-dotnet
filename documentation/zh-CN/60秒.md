# 60 秒看到一条追踪

[English](../sixty-seconds.md) | [Español](../es/sesenta-segundos.md) | [Português](../pt-BR/sessenta-segundos.md) | **简体中文**

没有日志语句，没有测试框架，没有需要打开的文件：一个控制台应用，一次
`dotnet run`，追踪就在你的终端里。下面的一切都是真实运行过的 — 输出是
粘贴过来的，不是想象出来的。（单包安装 *(since 0.1.4, unreleased)* 是这个
代理带来的依赖图；在
`0.1.3`（当前 nuget.org 发布版）上，还要手动添加 `.Runtime` 和 `.Core`
— 见下文。）

## 1. 新建控制台应用，添加这个包

```bash
dotnet new console -n Hello && cd Hello
dotnet add package NarrativeTrace.Proxy
```

只需一个包：`NarrativeTrace.Proxy` 依赖 `NarrativeTrace.Runtime`，后者又
依赖 `NarrativeTrace.Core` — `dotnet add package` 会解析整条依赖链，所以
下面用到的 `SyncNarrativeContext` 和 `IndentedTextRenderer` 不需要再额外
执行两次 `dotnet add package` *(since 0.1.4, unreleased)*。在 `0.1.3` 上，
`Proxy` 只依赖 `Core`；在
`0.1.4` 发布之前，三个包都要装：

```bash
dotnet add package NarrativeTrace.Core
dotnet add package NarrativeTrace.Runtime
dotnet add package NarrativeTrace.Proxy
```

## 2. 替换 Program.cs

```csharp
using NarrativeTrace.Core;
using NarrativeTrace.Proxy;
using NarrativeTrace.Runtime;

var context = new SyncNarrativeContext(new NarrativeTraceConfig());
var orders = NarrativeTraceProxy.Create<IOrderService>(new OrderService(), context);

orders.PlaceOrder("cust-1", "book-123", 2);

Console.WriteLine(IndentedTextRenderer.Render(context.CaptureTrace()));

public interface IOrderService
{
    string PlaceOrder(string customerId, string productId, int quantity);
}

public sealed class OrderService : IOrderService
{
    public string PlaceOrder(string customerId, string productId, int quantity)
        => $"confirmed:{customerId}:{productId}:{quantity}";
}
```

## 3. 运行它

```bash
dotnet run
```

```text
└── IOrderService.PlaceOrder(customerId: "cust-1", productId: "book-123", quantity: 2) → "confirmed:cust-1:book-123:2" — 9ms
```

(每次运行耗时会有所不同 — 其余部分都是稳定的。)

你没有写过一条日志语句。这条叙事完全来自你的方法名、参数名，以及你返回
的值。

## 刚刚发生了什么

- `NarrativeTraceProxy.Create<T>` 把 `OrderService` 包装在它的
  `IOrderService` 接口之下，并记录每一次通过这个包装器发起的调用。
- `SyncNarrativeContext` 把这次记录保存在内存中；`NarrativeTraceConfig()`
  默认就是 `TracingLevel.Detail` — 完整捕获参数与返回值，不需要打开任何
  开关。
- `CaptureTrace()` 返回被记录的树；上面就是 `IndentedTextRenderer` 打印出
  的结果。`MarkdownRenderer` 和 `ProseRenderer` 能把同一棵树渲染成其他
  格式。包装一个会调用其他已追踪服务的服务，这棵树就会嵌套 — 一次调用，
  一个故事。

## 把它发送到你的日志库

再加两个包，同一棵已捕获的树，没有新的捕获逻辑 — `TraceLogExporter` 会把
它重放到你的应用已经接好的那个 `ILogger` 上。

```bash
dotnet add package NarrativeTrace.Logging
dotnet add package Microsoft.Extensions.Logging.Console
```

```diff
+using Microsoft.Extensions.Logging;
 using NarrativeTrace.Core;
+using NarrativeTrace.Logging;
 using NarrativeTrace.Proxy;
 using NarrativeTrace.Runtime;

 var context = new SyncNarrativeContext(new NarrativeTraceConfig());
 var orders = NarrativeTraceProxy.Create<IOrderService>(new OrderService(), context);

 orders.PlaceOrder("cust-1", "book-123", 2);

-Console.WriteLine(IndentedTextRenderer.Render(context.CaptureTrace()));
+var tree = context.CaptureTrace();
+Console.WriteLine(IndentedTextRenderer.Render(tree));
+
+using var loggerFactory = LoggerFactory.Create(builder => builder.AddConsole());
+TraceLogExporter.ExportToLogger(tree, loggerFactory.CreateLogger("NarrativeTrace"));
```

```bash
dotnet run
```

```text
└── IOrderService.PlaceOrder(customerId: "cust-1", productId: "book-123", quantity: 2) → "confirmed:cust-1:book-123:2" — 0ms

info: NarrativeTrace[1]
      IOrderService.PlaceOrder(customerId: "cust-1", productId: "book-123", quantity: 2) -> "confirmed:cust-1:book-123:2"
```

（每次运行耗时会有所不同 — 其余部分都是稳定的。）

同一条追踪，两个目的地：控制台渲染器保持完全不变，下面这条 `ILogger`
记录则证明这棵树确实落到了你已经在用的那个接收端 — 把 `AddConsole()`
换成你真正的 provider，其余什么都不用改。`NarrativeTrace.Logging` 的其他
入口（`LoggingNarrativeContext` 用于按调用实时记录日志，
`AddNarrativeLogging()` 用于 DI）见
[安装指南](../guides/zh-CN/安装指南.md)。

## 接下来

- **把它用在你的测试里，或者接入 DI / ASP.NET Core** —
  [选择集成方式](选择集成方式.md)是决策图；
  [安装指南](../guides/zh-CN/安装指南.md)有完整的包和接线参考。
- **让某个值不出现在追踪里** — `[NotTraced]`、始终生效的名称拒绝列表，
  以及不含值的 `.nt` 结构化产物，是三层各自独立的防线 — 参见
  [隐私与脱敏](隐私与脱敏.md)。
- **为你的命名打分** — 把 `PlaceOrder` 重命名为 `Process`，其余保持不变，
  清晰度评分就会下降 — 参见[清晰度指南](../guides/zh-CN/清晰度指南.md)。
- **每一个开关** — [配置指南](../guides/zh-CN/配置指南.md)：追踪级别、
  输出格式，以及每一个 `NARRATIVETRACE_*` 变量。
- **遇到问题了？** — [故障排查](故障排查.md)：大家实际会遇到的失败模式的
  症状 → 原因 → 修复。
