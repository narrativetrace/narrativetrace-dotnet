# 隐私与脱敏

[English](../privacy-and-redaction.md) | [Español](../es/privacidad-y-ocultacion.md) | [Português](../pt-BR/privacidade-e-ocultacao.md) | **简体中文**

NarrativeTrace 运行在你的进程内部，写出你的团队会共享的文件 — CI 产物、
本地追踪输出，或者你的日志管道会转发的任何东西。这一页准确说明了什么会
被脱敏、什么不会，都是对照这个 port 的代码验证过的(不是假设的，也不是从
Java 参考实现照搬过来的)，这样你在接入之前就能判断它对你的数据是否安全。

## 脱敏，逐个接入方式

这个 port 里每一种发布出去的集成方式都通过同一个引擎(`ValueRenderer`、
`NarrativeInterceptor`)渲染参数和返回值，而这个引擎总是解析到
`RedactionPolicy.Default` — 没有一种集成方式暴露出可以关闭它的配置开关：

| 接入方式 | 能关闭内置脱敏吗? | 为什么 |
|---|---|---|
| `NarrativeTraceProxy.Create<T>`(原生 `DispatchProxy` 捕获) | 不能 | 渲染每一个参数/返回值时完全不带任何 `RenderOptions` 参数 — 始终是 `RedactionPolicy.Default`。 |
| DI 自动包装(`AddNarrativeTracing`) | 不能 | 内部用 `NarrativeTraceProxy.Create` 包装；`NarrativeTracingDiOptions` 没有任何脱敏字段。 |
| ASP.NET Core 中间件 | 不能 | `NarrativeTraceOptions` 没有任何脱敏字段；追踪来自不管哪条 proxy 路径产出的结果。 |
| xUnit 的 `NarrativeFixture` | 不能 | 这个类型里任何地方都没有 `RedactionPolicy`/`RenderOptions` 参数。 |
| NUnit 的 `NarrativeTestBase` | 不能 | 与 xUnit fixture 形状相同。 |
| `[Narrated]` / `[OnError]` 模板占位符(`NarrationResolver`) | 不能 | 完全静态的类，硬编码为 `RedactionPolicy.Default` — 参见下面更窄的那个缺口。 |
| 规范 JSON / 结构化 JSON 投影 | 不适用 — 没什么可关的 | 消费的是已经渲染过(已经脱敏过)的字符串；结构化投影还会无条件地剔除每一个值。 |
| 结构化 `.nt` 产物 | 不适用 — 不存在值 | `StructuralTraceRenderer` 只输出名称、层级和结果类型，从不输出值。 |
| `dotnet-narrativetrace clarity-scan` | 不适用 — 从不读取值 | 仅基于 `MetadataLoadContext` 的反射：它从不构造实例，也不调用任何东西，所以根本没有值需要脱敏。 |
| 在**你自己的代码**里自定义调用 `ValueRenderer.Render(value, options)` | 能 | 代码库里唯一的逃生舱口：自己传入 `new RenderOptions(Redaction: RedactionPolicy.Disabled)`。即便如此，`[NotTraced]` 仍然会脱敏。 |

最后那一行是唯一诚实的例外，而且是刻意为之，不是疏忽：
`RedactionPolicy.Disabled` 作为一个库原语是存在的
(`RedactionPolicy.Disabled = new([], valueShapesEnabled: false)`)，但没有
任何发布出去的集成方式会把它接上。要触达它，意味着你要自己写一个带显式
`RenderOptions` 的 `ValueRenderer.Render`/`RenderStructured` 调用 — 这是
你自己源码里一个刻意的、可评审的行为，从来不是一个开关或环境变量。

## 拒绝列表能捕捉什么，什么规则优先于它

`RedactionPolicy.Default` 匹配 26 个不区分大小写的名称模式，而不是你随手
翻一眼 FAQ 就能猜到的那个更短的 "password、cvv、ssn、token、secret、
authorization" 集合：

```
password, passwd, secret, token, apikey, api_key, cvv, ssn, authorization,
credential, privatekey, private_key, cardnumber, card_number, jwt, cookie,
setcookie, set_cookie, sessionid, session_id, accountnumber, account_number,
routingnumber, routing_number, pan, iban
```

匹配是基于子串的，而且刻意偏向过度脱敏(`token` 这个模式也会捕捉到
`apiTokenValue`) — 除了 `pan` 和 `iban`，如果按子串匹配，它们会连带
遮蔽掉普通的业务字段(`companyName`、`planId`、`spanCount`、
`japaneseAddress`)，所以这两个改成按标识符的词法边界匹配。

与字段名无关，第二条轴线识别三种**值形态**，不管字段叫什么名字都会脱敏：
一个 JWT(三段 base64url，首段以 `eyJ` 开头)、一个通过 Luhn 校验的
13–19 位支付卡号，以及一个 HTTP `Set-Cookie` 形态的字符串。这就是为什么
一个叫 `data` 或 `note` 的字段，只要碰巧装着看起来像卡号或 bearer token
的东西，照样会被脱敏。

`[NotTraced]` 加在参数、属性或字段上时总是优先于拒绝列表，与它无关：

- 加在属性/字段上时，值的 getter **完全不会被调用** — 脱敏检查在反射
  触及这个成员之前就已经运行，而不是之后。
- 加在 proxy 参数上时，参数已经被调用方求过值了(对一次真实的方法调用来说
  这是不可避免的)，但 NarrativeTrace 本身从不渲染它 — 标记在
  `ValueRenderer` 看到它之前就已经被替换掉了。
- 它优先于*容器*成员上一个精心编写的 `ToString()` 和一个
  `[NarrativeSummary]` 方法：脱敏检查在到达两者之前就已经完成。
- 字典的**键**走的是与值相同的受保护路径 — 一个名字敏感的键，脱敏方式
  与一个名字敏感的属性完全一样，永远不会通过裸的 `ToString()` 渲染。

那个更窄、已经知道的缺口：模板占位符解析(`[Narrated]`/`[OnError]`)是一条
完全静态的代码路径，始终使用 `RedactionPolicy.Default`。如果应用代码曾经
把一个*自定义* `RedactionPolicy` 直接接入 `ValueRenderer`(上面逃生舱口
那一行反过来用 — 是收紧而不是关闭)，那个自定义策略会在所有手动调用
`ValueRenderer` 的地方生效，但**不会**在 `[Narrated]`/`[OnError]` 模板
内部生效，它们始终使用默认拒绝列表，无论如何。今天没有任何发布出去的
集成方式会接入自定义策略，所以这一点只有在你自己直接针对
`NarrativeTrace.Core` 的渲染 API 编程时才重要。

## 边界与转义

不管是否脱敏，每一个渲染出来的值都有上限，并且会被净化：

| 控制项 | 默认值 |
|---|---|
| 最大字符串长度 | 200 个字符，之后接一个 `"...(truncated)"` 风格的后缀 |
| 最大集合项数 | 5，之后接一个 `(N total)` 摘要 |
| 最大对象键数 | 5 |
| 最大嵌套深度 | 4 |
| 循环检测 | 基于引用同一性，与深度无关 |
| 控制字符 / 日志注入转义 | 控制字符和不成对的代理项会被转义成 `\uXXXX`(引号/反斜杠是序列化器的职责，不是渲染器的) |

## 保证

- **脱敏在每一种发布出去的集成方式里都是无条件的。** `[NotTraced]` 和
  26 个模式的拒绝列表(加上三种值形态)适用于这个 port 发布的每一条输出
  路径 — proxy 捕获、DI 自动包装、ASP.NET Core 中间件、xUnit/NUnit 测试
  输出、模板占位符，以及每一种导出格式。没有任何开关、环境变量或 MSBuild
  属性能关闭它们。
- **结构化产物完全不携带任何运行时值。** `.nt` 文本产物和可选开启的
  `.structural.json` 条目数组都会剔除每一个参数值、返回值和异常消息 —
  一个属性测试会向一条已捕获条目的每一个值字段注入恶意内容，只要有任何
  一点存活到了投影结果里，测试就会失败。
- **渲染不能让你的应用崩溃。** 捕获和渲染在每一个风险点上都是异常隔离的：
  一个会抛异常的自定义 `ToString()`、一个会抛异常的 `[NarrativeSummary]`
  成员、一个在模板里被点名的会抛异常的属性 getter、一个恶意的枚举器或
  字典 — 每一种都会退化为一个占位符，而不会中止这次调用、这个集合或这条
  追踪。
- **资源使用是有界的。** 长度、集合大小、对象宽度和嵌套深度全部都有上限，
  加上与深度无关的、基于引用同一性的循环检测。
- **输出无法被伪造。** 控制字符和不成对的代理项，在一个渲染出来的值到达
  文件之前就已经被转义，所以一个恶意的值无法注入一条伪造的日志行，也无法
  破坏 Markdown/JSON/图表的语法。

## 非保证

- **没有任何发布出去的集成方式能让你关闭脱敏。** 唯一的逃生舱口是应用
  代码自己构造一个带 `RedactionPolicy.Disabled` 的 `ValueRenderer.Render`
  调用 — 这是你自己源码里的一个刻意行为，从来不是一种配置状态。即便在
  `Disabled` 之下，`[NotTraced]` 仍然会脱敏。
- **模板占位符不遵循自定义的 `RedactionPolicy`。**
  `[Narrated]`/`[OnError]` 的解析始终使用默认拒绝列表，哪怕你在别处把一个
  自定义策略接入了 `ValueRenderer`。
- **检测是基于名称和形态的，不是统计意义上的。** 没有信息熵之类的、"看起来
  随机"的启发式判断 — 一个躺在名字无害、形态不被识别的字段里的机密不会被
  捕捉到。这是一道后备防线，不是"每一个机密都会被找到"的保证。
- **一个值自己的 `ToString()`/`[NarrativeSummary]` 是被信任的代码。** 一旦
  一个值被单独捕获(不是躲在一个被脱敏的成员后面)，渲染器就会信任那个
  类型的摘要方法选择暴露出来的任何东西 — 这与你在调试器里读到的手写
  `ToString()` 的信任模型是一样的。如果一个类型自己的摘要不能被信任放进
  某个字段，就在那个*成员*上标注 `[NotTraced]`。
- **目前还没有任何生产环境的基线比较循环会把结构化产物读回来。** `.nt`
  文件按构造是确定性的、不含值的，但这个 port 没有发布任何东西会把它与
  上一次运行做比较(参见[应提交的内容](应提交的内容.md))。
