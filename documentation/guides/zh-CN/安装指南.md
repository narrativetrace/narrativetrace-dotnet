# NarrativeTrace .NET — 安装指南

[English](../installation.md) | [Español](../es/guia-de-instalacion.md) | [Português](../pt-BR/guia-de-instalacao.md) | **简体中文**

本指南介绍如何在 .NET 项目中安装并接入 NarrativeTrace。

## 前置条件

- 构建需要 .NET 10 SDK；类库以 `net10.0` 和 `netstandard2.0` 多目标框架
  编译，因此可以运行在任何支持 netstandard2.0 的 .NET 运行时上
  (.NET Core 2.0+、.NET 5+，以及通过 `Legacy` 包支持的 .NET Framework
  4.8)。
- **无需任何编译器参数。** 与 JVM(需要 `-parameters`)不同，.NET 默认就
  在元数据中保留方法参数名，因此追踪开箱即用地显示真实名称。只有在你想
  覆盖某个名称时才使用 [`[Traced]`](特性指南.md#traced) 特性。

## 包

`src/` 下的每个项目都以同名 NuGet 包发布。从最小集合开始，按需添加。

```xml
<!-- 最小集合：捕获 + 渲染 -->
<PackageReference Include="NarrativeTrace.Proxy" Version="0.1.4" />
```

`NarrativeTrace.Proxy` 依赖 `.Runtime`，后者又依赖 `.Core` —— 一次
`dotnet add package NarrativeTrace.Proxy` 就能把三个包都还原出来，它们的
类型(`SyncNarrativeContext`、`IndentedTextRenderer` 等)可以直接拿来用
*(since 0.1.4, unreleased)*。
在 `0.1.3` 上，`Proxy` 只依赖 `Core`；在 `0.1.4` 发布之前，请显式添加
三个包：

```xml
<PackageReference Include="NarrativeTrace.Core" Version="0.1.3" />
<PackageReference Include="NarrativeTrace.Runtime" Version="0.1.3" />
<PackageReference Include="NarrativeTrace.Proxy" Version="0.1.3" />
```

| 包 | 何时添加 |
|---|---|
| `NarrativeTrace.Core` | 始终 — 追踪模型、`INarrativeContext`、配置、脱敏、Markdown/Prose/文本渲染器，以及 `[Narrated]`/`[OnError]`/`[NotTraced]`/`[NarrativeSummary]` 特性(命名空间 `NarrativeTrace.Core.Annotation`)。由 `.Runtime` 传递带入 *(since 0.1.4, unreleased)*。 |
| `NarrativeTrace.Runtime` | 始终 — 捕获引擎(`SyncNarrativeContext`、`AsyncNarrativeContext`、JSON/章节导出器)。由 `.Proxy` 传递带入 *(since 0.1.4, unreleased)*。 |
| `NarrativeTrace.Proxy` | 通过 `DispatchProxy` 进行接口追踪，外加 proxy 专属的 `[Traced]` 参数名覆盖，以及 `ProxyOptions.Redaction`(为该 proxy 的捕获指定自定义 `RedactionPolicy` —— 参见[配置指南 §6](配置指南.md#6-脱敏))。 |
| `NarrativeTrace.DependencyInjection` | `AddNarrativeTracing` — 在 MS.DI 容器中自动包装按命名空间匹配的接口服务。 |
| `NarrativeTrace.AspNetCore` | 面向 ASP.NET Core 的按请求追踪生命周期中间件。 |
| `NarrativeTrace.Testing.Xunit` | `NarrativeFixture` — 按测试的上下文与失败叙事打印(命名空间 `NarrativeTrace.TestingXunit`)。 |
| `NarrativeTrace.Testing.NUnit` | `NarrativeTestBase` — NUnit 的同等能力(命名空间 `NarrativeTrace.TestingNUnit`)。 |
| `NarrativeTrace.Diagrams` | Mermaid / PlantUML 时序图渲染器。 |
| `NarrativeTrace.Clarity` | 命名清晰度分析与报告(`ClarityScanner`、`ClarityAnalyzer`)。 |
| `NarrativeTrace.Observability` | OpenTelemetry 桥接 — 通过 `System.Diagnostics.ActivitySource` 进行批量导出与实时 Span 创建。 |
| `NarrativeTrace.Logging` | `Microsoft.Extensions.Logging` 桥接(`LoggingNarrativeContext`、`TraceLogExporter`、`AddNarrativeLogging()`)。 |
| `NarrativeTrace.Cli` | `dotnet-narrativetrace` 全局工具 — 仅基于反射的清晰度扫描 + CI 门禁。 |
| `NarrativeTrace.MSBuild` | 仅构建期的包，把 CLI 接入 `dotnet build` / `dotnet test`。 |

> 版本处于 1.0 之前(写这段文字时 nuget.org 上是 `0.1.3`，接下来是
> `0.1.4`)。请使用你实际安装的版本；并让所有 `NarrativeTrace.*` 包保持
> 同一版本。

## 选择一种集成方式

### 方式 A — DispatchProxy(适用于任何 .NET 应用)

包装一个以接口为类型的服务；经过该 proxy 的每次调用都会记录到共享上下文中。

```csharp
using NarrativeTrace.Core;
using NarrativeTrace.Proxy;
using NarrativeTrace.Runtime;

var context = new SyncNarrativeContext(
    new NarrativeTraceConfig(TracingLevel.Detail));

var orders = NarrativeTraceProxy.Create<IOrderService>(
    new DefaultOrderService(), context);

orders.PlaceOrder("C-1234", "SKU-KB", 2);

Console.WriteLine(IndentedTextRenderer.Render(context.CaptureTrace()));
context.Reset();
```

当你的服务基于接口时使用这种方式。在相互协作的服务之间共享**同一个**
上下文，它们的调用才会嵌套成一棵树。

### 方式 B — 依赖注入自动包装

Spring/Micronaut Bean 自动包装在 `.NET` 中的等价物。像平常一样注册服务，
然后包装那些实现类命名空间匹配某个前缀的服务：

```csharp
using NarrativeTrace.DependencyInjection;

services.AddScoped<IOrderService, DefaultOrderService>();

services.AddNarrativeTracing(options => options
    .Namespaces("MyApp.Services", "MyApp.Payments"));
```

只有以**接口**注册、且实现类命名空间匹配已配置前缀的服务才会被包装。
Scoped 的 `INarrativeContext` 会自动注册。选项详见
[配置指南](配置指南.md#3-依赖注入)。

### 方式 C — ASP.NET Core 请求追踪

添加服务，并把中间件放在管道靠前的位置。每个请求都会获得一份新的追踪
(存放在 `HttpContext` 中)，请求结束时由中间件捕获并导出。通过解析这个
按请求的上下文来追踪你的服务：

```csharp
using NarrativeTrace.AspNetCore;
using NarrativeTrace.Proxy;

builder.Services.AddNarrativeTrace(builder.Configuration);

var app = builder.Build();
app.UseMiddleware<NarrativeTraceMiddleware>();

app.MapGet("/orders/{id}", (string id, HttpContext http) =>
{
    var orders = NarrativeTraceProxy.Create<IOrderService>(
        new DefaultOrderService(), http.GetNarrativeContext());
    return orders.FindOrder(id);
});
```

导出器、排除路径以及请求/用户上下文，详见
[ASP.NET Core 集成指南](ASP.NET-Core集成指南.md)。

### 方式 D — xUnit 自动上下文 + 失败叙事

```csharp
using NarrativeTrace.Proxy;
using NarrativeTrace.TestingXunit;   // 注意：Xunit 前面没有点
using Xunit;

public sealed class OrderServiceTests
{
    [Fact]
    public void Customer_places_order()
    {
        using var narrative = new NarrativeFixture();

        narrative.Run("Customer places order", context =>
        {
            var orders = NarrativeTraceProxy.Create<IOrderService>(
                new DefaultOrderService(), context);
            orders.PlaceOrder("C-1234", "SKU-KB", 2);
        });
    }
}
```

用 `using var` 为每个测试创建一个 `NarrativeFixture`，这样每个测试都有
干净的上下文(释放时会重置)。当方法体抛出异常时，`NarrativeFixture.Run`
会把捕获到的叙事打印到控制台，然后重新抛出 — 于是失败的测试会自己解释
自己。

### 方式 E — NUnit 自动上下文 + 失败叙事

```csharp
using NarrativeTrace.Proxy;
using NarrativeTrace.TestingNUnit;   // 注意：NUnit 前面没有点
using NUnit.Framework;

public sealed class OrderServiceTests : NarrativeTestBase
{
    [Test]
    public void Customer_places_order()
    {
        var orders = NarrativeTraceProxy.Create<IOrderService>(
            new DefaultOrderService(), Context);
        orders.PlaceOrder("C-1234", "SKU-KB", 2);
    }
}
```

`NarrativeTestBase` 会为每个测试打开新的上下文(`[SetUp]`)，并在失败时
打印叙事(`[TearDown]`)。重写 `OnTraceComplete` 可以写入文件或运行清晰度
分析。

### 方式 F — `dotnet-narrativetrace` CLI

安装全局工具，直接从编译好的程序集分析命名清晰度 — 无需运行测试：

```bash
dotnet tool install --global NarrativeTrace.Cli

dotnet-narrativetrace clarity-scan --assembly bin/Release/net10.0/MyApp.dll
dotnet-narrativetrace clarity-check --results clarity-results.json --min-score 0.80 --max-high-issues 0
```

评分模型与 CI 门禁详见[清晰度指南](清晰度指南.md)。

### 方式 G — MSBuild 集成

添加仅构建期的包，让清晰度门禁成为构建的一部分：

```xml
<PackageReference Include="NarrativeTrace.MSBuild" Version="0.1.3"
                  PrivateAssets="all" />
```

它会注册 `ClarityScan` 与 `ClarityCheck` 目标，并把 `NARRATIVETRACE_*`
设置转发给测试宿主。阈值通过 MSBuild 属性配置(参见
[配置指南](配置指南.md#5-msbuild))。

## 配置追踪输出

类库通过 `ConfigResolver` 读取四个 `NARRATIVETRACE_*` 环境变量 — 这是
`.NET` 原生的覆盖通道：

| 变量 | 取值 | 默认值 |
|---|---|---|
| `NARRATIVETRACE_LEVEL` | `Off`、`Errors`、`Summary`、`Narrative`、`Detail` | `Detail` |
| `NARRATIVETRACE_OUTPUT` | `true` / `false`(也支持 `1` / `0`) | `true` |
| `NARRATIVETRACE_OUTPUT_DIR` | 任意可写路径 | `TestResults/narrativetrace` |
| `NARRATIVETRACE_FORMAT` | `Markdown`、`Text`、`Prose`、`Json` | `Markdown` |

无效取值会退化为默认值而不是抛出异常，因此错误的配置绝不会让捕获崩溃。
级别解析对大小写和标点是宽容的(`detail`、`DETAIL`、`Detail` 都能解析)。
`NARRATIVETRACE_OUTPUT` 默认开启 *(since 0.1.4, unreleased)* —— xUnit fixture 和 NUnit 基类会把按测试
产物写到 `TestResults/narrativetrace/`(临时目录，`.NET` 的 `TestResults/`
约定已经让 Git 忽略它)，不需要任何开关；设为 `false` 可以关闭。

## 验证安装

把一份追踪渲染到控制台：

```csharp
var context = new SyncNarrativeContext(
    new NarrativeTraceConfig(TracingLevel.Detail));
var svc = NarrativeTraceProxy.Create<IGreeter>(new Greeter(), context);
svc.Greet("world");
Console.WriteLine(IndentedTextRenderer.Render(context.CaptureTrace()));
```

你应当看到一段嵌套的叙事，其中包含方法名、参数值和返回值。
