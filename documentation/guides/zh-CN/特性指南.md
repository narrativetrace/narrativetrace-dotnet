# NarrativeTrace .NET — 特性指南

[English](../annotations.md) | [Español](../es/guia-de-atributos.md) | [Português](../pt-BR/guia-de-atributos.md) | **简体中文**

NarrativeTrace 奉行 **代码即日志** 的理念：方法名、参数名和返回值本身就
应该讲清楚运行时的故事。先让业务逻辑保持干净、富有表达力，再*例外地*
使用特性(Attribute) — 用于定点叙述、错误上下文、脱敏或自定义值渲染。

这四个叙事特性都位于 `NarrativeTrace.Core.Annotation` — 一条 `using` 即可
全部引入，而且它们和你的追踪模型来自同一个包。它们是纯粹的元数据：
`DispatchProxy` 拦截器(`NarrativeTrace.Proxy`)在它拦截的调用上读取
`[Narrated]`、`[OnError]` 和 `[NotTraced]`，而 `[NarrativeSummary]` 与
`[NotTraced]` 在任何渲染值的地方都会生效。`[Traced]` 是唯一的例外 — 它是
`DispatchProxy` 专属的标记，在 JVM 上没有对应物，因此仍留在
`NarrativeTrace.Proxy`。

```csharp
using NarrativeTrace.Core.Annotation;
```

## 清单

| 特性 | 命名空间 | 作用目标 | 用途 |
|---|---|---|---|
| `[NarrativeSummary]` | `NarrativeTrace.Core.Annotation` | 方法或属性 | 为其声明类型提供首选的摘要渲染。 |
| `[Narrated]` | `NarrativeTrace.Core.Annotation` | 方法 | 为被追踪的方法添加人类可读的叙述文本。 |
| `[OnError]` | `NarrativeTrace.Core.Annotation` | 方法(可重复) | 为方法附加与上下文相关的错误文本。 |
| `[NotTraced]` | `NarrativeTrace.Core.Annotation` | 参数、属性、字段 | 在追踪输出中对值脱敏，包括被内省对象的成员。 |
| `[Traced]` | `NarrativeTrace.Proxy` | 方法 | 按位置覆盖捕获到的参数名。 |

## `[Narrated]`

当你希望追踪中出现一句明确的话，而不是只依赖方法名加参数时，使用
`[Narrated]`。

```csharp
public interface IOrderService
{
    [Narrated("Placing order of {quantity} units for customer {customerId}")]
    OrderResult PlaceOrder(string customerId, string productId, int quantity);
}
```

- 占位符使用**参数名**：`{customerId}`。
- 支持一层属性访问，成员名用 **PascalCase**：`{customer.Name}` 读取
  `customer` 实参的 `Name` 属性。
- 未知占位符在输出中保持**原样**(`{custmerId}` 会照样出现) — 这是内置的
  拼写错误信号。

**出现位置：** 叙述文本由 `MarkdownRenderer` 渲染，成功的节点上也由
`ProseRenderer` 渲染。它始终可以通过 `node.Signature.Narration` 以编程
方式获取。

## `[OnError]`

为异常附加特定上下文的文本。该特性**可重复**；设置 `ExceptionType` 可以
把模板限定到某个异常类型(默认为 `typeof(Exception)`)。

```csharp
public interface IPaymentService
{
    [OnError("Payment declined for {customerId}, amount was {amount}",
             ExceptionType = typeof(PaymentDeclinedException))]
    [OnError("Temporary payment failure for {customerId}",
             ExceptionType = typeof(ExternalServiceException))]
    PaymentConfirmation Charge(
        string customerId, decimal amount, [NotTraced] string token);
}
```

它在 .NET 中的工作方式(与 JVM 版一致)：

- 模板在**异常抛出时**解析，使用与 `[Narrated]` 相同的占位符规则，并存放
  为 `node.Signature.ErrorContext`。
- 只有声明的 `ExceptionType` 与**所抛异常匹配**(`IsInstanceOfType`)的特性
  才参与竞争；在匹配项中，声明类型最具体的胜出。不带类型的
  `[OnError("…")]`(隐式为 `typeof(Exception)`)匹配一切。
- 如果**没有**任何声明类型与所抛异常匹配，就不会附加错误上下文。正常返回
  的方法永远不会携带错误上下文。

**出现位置：** 在抛出异常的节点上，解析后的错误上下文由 `MarkdownRenderer`
和 `ProseRenderer` 渲染(位于异常之后)，并始终可通过
`node.Signature.ErrorContext` 获取。只渲染结构的 `IndentedTextRenderer`
不会显示它。

## `[NotTraced]`

标记敏感的**参数、属性或字段**，使其值在任何渲染或导出追踪的地方都被脱敏。
名称仍然可见；值会被替换为 `[REDACTED]`。

```csharp
public interface IAuthService
{
    Session Login(string username, [NotTraced] string password);
}
```

**嵌套在被追踪对象内部**的机密有两重覆盖，与 JVM 版默认脱敏的立场一致：

- **基于名称的拒绝列表** — 反射渲染会通过 `RedactionPolicy` 自动脱敏常见
  的敏感成员名(`password`、`token`、`cvv`……)，参见
  [配置指南](配置指南.md#6-脱敏)。
- **在成员上标注 `[NotTraced]`** — 对于名称不匹配任何模式的机密，请标注
  属性、字段或 record 的位置参数；渲染器会在内省期间替换为标记，且与拒绝
  列表无关(即使 `RedactionPolicy.Disabled` 也依然生效)：

```csharp
public sealed record Card(string Last4, [NotTraced] string Pan);

public sealed class Payment
{
    public decimal Amount { get; init; }

    [NotTraced]
    public string ProcessorReference { get; init; } = "";
}
```

- 典型用途：密码、token、机密、卡片数据。

**脱敏优先于点名它的模板。** `[Narrated]` 与 `[OnError]` 会在原始参数上
解析 `{param.Property}` 路径,而一条抵达被脱敏属性的路径解析结果为
`[REDACTED]`——绝不是它的值,也绝不是原样保留的占位符。点名一条路径,绝
不会削弱直接作用于该值的规则。如果你确实需要在叙述中呈现这个值,请从该
属性上移除 `[NotTraced]`;这一移除动作才是刻意做出、可供评审的决定,并
且会清楚地出现在 diff 中。

## `[Traced]`

`.NET` 默认在元数据中保留参数名，因此与 JVM 不同，你很少需要它。使用
`[Traced]` 可以按位置**覆盖**捕获到的参数名，例如给出比源码标识符更清晰
的领域名称：

```csharp
public interface IMessageBus
{
    [Traced("messageId", "payload")]
    void Publish(string id, object body);
}
```

参数 `id` 会被捕获为 `messageId`，`body` 被捕获为 `payload`。给出的名称
少于参数个数也没问题 — 未列出的位置保留其反射得到的名称。

## `[NarrativeSummary]`

为值渲染提供简短、经过打磨的摘要。把它应用在公共的**无参方法或属性**上；
每当该类型的实例被渲染时，就会使用它的结果(经由 `ToString()`)。

```csharp
public sealed record Customer(string Id, string Name, CustomerTier Tier)
{
    [NarrativeSummary]
    public string Summary => $"Customer[id={Id}, tier={Tier}]";
}
```

- `ValueRenderer` 会先查找 `[NarrativeSummary]` 成员，然后才回退到 record
  渲染、反射属性与字段内省或 `ToString()`。
- 该成员必须是公共的且不接受参数。
- 该特性会被**继承** — 基类型的摘要适用于派生类型，除非被覆盖。
- 如果调用它时抛出异常，则应用渲染器的常规回退。它在任何渲染值的地方
  都会生效(所有渲染器与导出器)。

## 纯净性契约 — 追踪期间的副作用

NarrativeTrace 在渲染追踪时，可能会在你的对象上调用一小组固定的代码路径。
请让这些成员保持**纯净** — 没有懒加载、访问计数、缓存填充或 I/O 之类的
副作用 — 就像你为调试器或序列化器所做的那样。这一点在 .NET 上比在其他
平台更重要，因为地道的 C# 状态藏在*属性*背后，而属性的 getter 就是方法：
读取它可能执行任意代码。

渲染期间会调用什么：

- **反射内省会读取属性和字段。** 当一个实例既没有精心编写的 `ToString()`
  也没有 `[NarrativeSummary]` 成员时，带副作用的属性 getter(计数器、
  懒初始化、一次数据库往返)*一定*会被执行。.NET Framework 设计准则本身
  就要求 getter 无副作用；NarrativeTrace 依赖这一约定。
- 同样会被调用的还有：自定义的 `ToString()`、`[NarrativeSummary]` 成员，
  以及 `[Narrated]`/`[OnError]` 模板中出现的属性路径(`{order.Total}`)。

暴露面是如何被限制的：

- **有界** — 字符串长度、集合元素数量和内省深度的上限限制了可执行的代码量。
- **异常隔离** — 抛异常的 getter 或 `ToString()` 绝不会让被追踪的业务调用
  失败；模板会回退为字面量 `{占位符}`，渲染会回退为类型名标记。
- **立即且确定** — 值在调用点就被渲染，因此任何副作用只发生一次，时机可
  预测，并且在调用线程上。
- **可跳过** — 属性或字段上的 `[NotTraced]` 意味着其值根本不会被读取
  (只输出 `[REDACTED]` 标记)；精心编写的 `ToString()`/`[NarrativeSummary]`
  优先于内省，因此你能精确控制访问了什么；而在 `TracingLevel.Off` 下
  (以及 `Summary` 下的参数值)完全不会发生任何渲染。

如果某个成员无法保持纯净，请用 `[NotTraced]` 标记它，或把它藏在精心编写
的摘要后面。不要指望追踪总是处于关闭状态。

## 完整示例

```csharp
public interface ITransferService
{
    [Narrated("Transferring {amount} from {fromAccountId} to {toAccountId}")]
    [OnError("Transfer rejected for source account {fromAccountId}",
             ExceptionType = typeof(InvalidOperationException))]
    TransferResult Transfer(
        string fromAccountId,
        string toAccountId,
        decimal amount,
        [NotTraced] string authToken);
}
```

一个方法，同时用上了叙述文本、定点错误上下文和参数脱敏。

## 模板中的拼写错误

`[Narrated]` 与 `[OnError]` 模板使用 `{paramName}` 和
`{paramName.Property}` 占位符。匹配不到任何参数的占位符会在解析后的文本
中保持原样(`{custmerId}` 会照样出现)，未知属性则渲染为 `{propertyName}`。

**被脱敏的属性解析为 `[REDACTED]`**——既不是它的值，也不是原样保留的占位
符。脱敏规则的两半都会生效：属性上的 `[NotTraced]`（包括记录的位置参
数），以及作用于任何特性都未覆盖的属性的基于名称的拒绝列表。没有点名任
何参数的占位符，或其所有者并未声明的属性，仍会原样保留——那属于书写错
误，背后并不存在任何值。

xUnit fixture 与 NUnit 基类会在测试之后扫描每份捕获到的追踪，并把残留的
占位符作为警告打印出来，因此模板里的拼写错误会在测试期间浮现：

```
WARNING: Unresolved template placeholder(s) detected:
  - OrderService.PlaceOrder: {custmerId} in narration
```

使用 `TemplateWarningCollector.Collect(tree)` 可以自己运行同样的扫描。
